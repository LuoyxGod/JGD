# 拼图容器与自动网格对齐 · 实施计划书 v1.2

> 背景：网页编辑器产出关卡 JSON → Unity 内按拼图逐个建模 → 存入容器 → 按地块大小自动配网格：先场景视窗预览，确认后生成实体布局。
> 项目：JGDgame（Unity 6000.4.11f1，URP，Odin 已装）。测试场景：SampleScene / TestLevel（临时搭建物，由你自己整理）。
> v1.2 变更：去掉「隐藏/显示 TestLevel」开关；保留"正式布局生成在独立 PuzzleLevel 根节点下物理隔离"。

---

## 一、职责划分

| 角色 | 职责 | 不负责 |
|---|---|---|
| 网页编辑器 | 产出关卡 JSON：形状/道路/出口/出生点/记忆物/参数 | 建模、摆放、玩法 |
| Unity 建模者（你） | 按 JSON 规划在场景中逐拼图建模 → 存入容器 | 对齐计算（工具自动） |
| Unity 工具 | 容器管理、JSON 导入、场景视窗网格预览、布局生成、尺寸缩放 | 建模内容、场景整理 |
| 玩法层（后置） | UI 2D 拼图界面把摆放结果传给本系统 → 按网格正确生成区域；通行/记忆物 | —— |

## 二、容器选型

**采用：Prefab 资产 + PuzzleRegistry（ScriptableObject，Odin 强化）索引。**

- SO 不存场景对象 → 场景中建好的拼图根节点通过「存入容器」**另存为 Prefab 资产**，Registry 只登记引用与元数据（形状数据来自 JSON，不重复存场景结构）；
- 好处：打包安全、运行时可按 JSON 重新实例化、Prefabs 资产可进版本管理；
- 否决：SO 直接引用场景对象（换场景/打包失效）；Odin 序列化整棵子物体再代码重建（过度工程）。

**拼图唯一键（名词解释）**：就是编辑器里给拼图起的名字，是 JSON、容器条目、Prefab、场景组装节点四者互相"认亲"的身份证。要求**同一关内不重名**；导入时发现重名会提示。定稿后别轻易改名（改名=换身份，容器对应关系要手动重指）。

## 三、数据流与工作流

```
网页编辑器 ─复制JSON─▶ 导入窗口：解析 → PuzzleRegistry 自动生成条目（状态=未建模）
      │
      ▼
场景建模：新建 PZ_拼图名 根节点，按 cells 规划建模（地块大小见参数）
      │
      ▼ 「存入容器」（组装节点保留，由你移到远处留存调整）
另存 Prefab 资产 → Registry 条目更新（状态=已入库，引用+建模尺寸）
      │
      ▼ 「预览网格」（不生成实体，Scene 视窗画线）
Handles 画参考网格 + 各区域线框 + 名字/尺寸标签 + 出生点标记
      │  ← 确认整体地图生成位置的正确性
      ▼ 「生成布局」
初始图层按格坐标铺开（含出生点柱）｜已入库拼图按包围盒对齐+缩放落位
未建模拼图摆半透明白盒占位
```

该网格体系即**以后拼图玩法的定位基础**：UI 2D 拼图界面确认摆放后，把结果传给本系统，系统按网格实例化对应区域。

## 四、对齐与缩放规则

1. 对齐：取 Prefab 全部 Renderer 联合包围盒 `bounds.min.xz` 平移到目标格点（建模原点误差自动兜底；尺寸本身仍需建模者按 cells×tileSize 把控）；
2. 缩放：根节点 `localScale ×= 当前地块大小 ÷ 建模时地块大小`（每条目独立记录建模尺寸）；
3. 占位块：未入库拼图按 cells 程序化生成半透明白盒（对齐规则相同）；
4. 出生点：初始图层 spawn 格中心放标记柱（临时几何体，后续换美术）；
5. 网格线：按 tileSize 绘制，可开关。

Prefab 与拼图形状的对应关系由 Registry 记录（名字即唯一键），程序不需要理解模型内部结构——尺寸误差你把控，位置误差工具兜底。

## 五、Unity 资产与脚本清单

```
Assets/
  Data/Levels/               ← JSON 文本资产
  Data/PuzzleRegistry.asset  ← 容器
  Prefabs/Regions/           ← 「存入容器」自动生成的拼图 Prefab
  Scripts/Level/
    PuzzleData.cs            ← LevelData/PieceData/Cell/Edge（兼容编辑器 JSON 结构）
    PuzzleRegistry.cs        ← 容器 SO（Odin TableList：名字/状态/Prefab槽/建模尺寸/完成勾选）
    PuzzleLevelBuilder.cs    ← 预览网格(Gizmos/Handles) + 布局生成/清理 + 占位块 + 出生点柱
  Scripts/Editor/
    PuzzleImporterWindow.cs  ← 菜单 JGD/拼图关卡导入器
```

导入器窗口分区：①JSON 粘贴/文件选择 → 导入；②条目表格（Odin）+「存入容器(用场景选中)」；③参数（当前/建模地块大小、网格线开关）→「预览网格」「生成布局」「清空布局」。

## 六、场景隔离规范

- 正式布局统一生成在独立的 `PuzzleLevel` 根节点下，与临时测试物（如 TestLevel）物理隔离；
- 临时测试物的整理由你自行处理，工具不做任何自动隐藏/删除。

## 七、里程碑与验收

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M1 导入 | 解析 JSON → Registry 条目自动生成（含重名提示） | 粘贴默认 JSON 出现全部条目 |
| M2 入库 | 场景选中 → 存 Prefab → 条目更新；组装节点保留 | Prefab 出现在 Prefabs/Regions，场景节点未被删动 |
| M3 预览 | Scene 视窗网格+区域线框+标签预览（含占位块、出生点） | 不生成实体即可确认整体位置 |
| M4 生成 | 实体布局 + 缩放 + 对齐 + 占位块/出生点柱 | 改地块大小重新生成，全部等比且贴网格 |

预计 M1-M4 合计 1~1.5 个工作日。
